# Supported local workspace lifecycle contract

## Observation and scope

The CLI initializes an explicitly created private ledger; configure admits bounded absolute local roots and authenticated accessible crucible-energy repository inventory. Repository ID plus verified Git origin identifies membership. Discovery includes registered non-lane workspaces and independent stores, reports coverage gaps and outside-visibility scope, and grants no creator authority.

## Event and status interface

SessionStart and delivery enqueue a hint and dispatch the independently verifying worker. SessionEnd only queues; it never releases ownership. Hooks pin their generating distribution and are printed for separate host trust/admission. Status distinguishes workflow completion, unresolved observations, pending generations, last worker outcome, exact organization scope/time/generation and whether that report matches current scope and hints. An empty, stale, corrupt or incomplete observation is not global cleanup success.

## Authority and effects

A supported new Git creator registers repository/store/path/ref/HEAD and workspace/lease generations before production. Its actual joined finite producer and private creating capability establish release. Exact accepted PR delivery is independently verified. The shared creator hold fences new leases through fresh preservation checks and guarded retirement. Discovery/event JSON cannot mint release or creator binding. Primary, active, dirty, valuable ignored, nested, unknown and unsupported managed work stays retained. Remote-branch disposition is separate and retained by this profile.

## Recovery

Persist intent before the creator effect and record the confirmed result. An unknown effect uses creator recovery, never blind replay. Missed completion events recover from durable creator facts on startup. One unavailable creator does not hide other observations. Failed inventory preserves obligations and a sanitized diagnostic; unchanged errors do not spin. Deadlines bound owned subprocesses and cooperatively stop filesystem traversal.

## Acceptance boundaries

Required positives are real nonempty Spec Kitty consolidation followed by joined completion and automatically dispatched cleanup, registered non-lane automatic retirement, missed-event replay and exact-once receipt. Required negatives include new generation/lease, stale or forged delivery/release, dirty/ignored/nested/active/primary preservation, corrupt private state and uncertain outcomes. Every code-kind and acceptance-artifact read uses the same admitted owned checkout; an absent matrix cannot be treated as a planning-only mission. Final source qualification records actual fresh-process timings and all selected gate outcomes, with independent canonical review. This contract grants no global hook trust, unsupported creator operation, PR merge or cloud deployment.
