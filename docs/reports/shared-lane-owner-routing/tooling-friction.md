# Findings and limitations

- Spec Kitty has AGENTS.md and a binding project charter; SAM.md is absent here.
- Installed dispatch folds to the dirty repository root checkout. This source
  repair remains under the parent's existing implement-review delegation rather
  than opening an unrequested Op on protected active state.
- Lane observer drift can mask a valid canonical claim. Warn-mode acceptance is
  not proof of ownership; the repair does not change the policy mode or bypass it.
- Native owned progression lost its explicit root after bootstrap and crossed to
  another checkout during WP mapping. A resolver-only correction is insufficient.
- An owned code-change prompt was labeled planning work and omitted checkout flags
  from lifecycle instructions; source instructions now preserve explicit routing.
- The minimal native test charter emits unresolved optional doctrine notices.
  These notices are retained; actual composition/guard failures are never mocked
  into passing. This fixture is code-contract proof, not deployed runtime evidence.
- No global install/release, active3body/PDB mutation or Temet lifecycle transition
  is part of this repair. Fixed source still requires independent review and normal
  delivery before runtime adoption.

- A first archived-baseline run accidentally loaded candidate source because
  pytest's configured `pythonpath` took precedence over the environment. It is
  retained as a misbound attempt, not a red reproduction. Repeating with the
  explicit pytest path override loads the immutable base and fails at the exact
  protected-checkout WP lookup reported by the 3body owner.
- An intermediate test run overlapped source formatting and failed an existing
  `inspect.getsource` assertion: the loaded function line number no longer matched
  the edited file. The failure is retained. That exact test passes on both stable
  candidate and immutable base; the complete stable-source run also passes.
- An attempted selective staging patch failed; subsequent commands committed
  only the ambiguity regression under a `fix:` prefix (`392818a1f`). Its production
  fix is in the following coherent source commit (`5aa5172de`). No source, protected
  checkout, test failure or PR67 history was discarded.

- Initial review fixtures lacked registered governance and attempted a planning
  ownership declaration rejected by modern finalization. Later historical fixture
  attempts also encountered the current mandatory lane authority. Those runs are
  retained as fixture failures, not production red/green evidence. The final
  historical formatter case supplies the nullable-lane workspace port explicitly;
  modern next, prompt, admission and invalid-base cases use their actual resolvers.
- One in-flight coverage run was stopped after invalid test expectations exposed
  the modern review-base mismatch. A second owned run was stopped before correcting
  an EOF formatting defect, rather than changing source during qualification.
  Both interrupted logs remain retained; neither is a passing gate.
- A supplementary coverage collection shared the default data location with an
  in-flight same-source run. Final coverage qualification uses a separate explicit
  data file and the frozen source so that no overlapping collection is its basis.

- The actual owned merge preview folded to the protected primary and refused
  its missing `lanes.json` before effects. No public external-GitHub-completion
  command exists; this repair does not invent one. Explicit-owned completion
  records local integration on the existing target, with remote delivery separate.
- New fixtures initially lacked required project directories and metadata; those
  setup failures are retained separately from the causal missing-option failure.
  An intermediate assertion incorrectly expected DoneEvidence in status.json;
  the canonical terminal event is its actual durable owner. No event/model state
  was altered to satisfy that assertion.
- The initial refusal response read the wrong property on ActionContextError;
  the exact `code` is now retained. A later identity check incorrectly treated
  off-axis annotations as lane events; the fixed check uses actual lane-event
  identities and annotation WP membership. Failed runs remain separate from the
  stable final proof. The canonical metadata-reader census is tightened for two
  new routed reads, with its four-site allowance unchanged.
- The existing golden helpers mistook the stock vendored Typer parser for an
  unrelated external Click class. Immutable c32 reproduces the failures. The
  separately authorized test-only repair uses native parser types/context and
  passes all unchanged baseline expectations; it is distinct from the new
  completion options and changes no production compatibility or dependencies.
